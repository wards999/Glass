# 0020 — M4 (robustness on Wi-Fi), in steps

**Status:** accepted · **Date:** 2026-11-23

## Context
Real sessions show what Wi-Fi does to the stream:
- occasional lost frames, each costing a keyframe request and a visible
  hitch (m5c-test9: "lost frames 2, keyframe requests 6");
- network-time spikes (p99 26 ms, max 63 ms).

SPEC §6b lists M4's parts. It's too much for one test build, so M4 goes in
steps, most visible first. Each step gets a test build and its own numbers
in `docs/results/M4.md`.

## Decision
1. **FEC** (m4-test1, protocol v10):
   - Systematic Reed–Solomon over GF(256), Cauchy matrix, in core
     (`fec.rs`). No new dependency.
   - Each frame's data packets are split into interleaved groups (packet i
     goes in group i mod G, at most 64 data packets a group). A burst of
     consecutive losses is then spread over the groups.
   - Each group gets parity packets.
   - The amount follows the loss the viewer reports (a `ReceiverReport`
     every 0.25 s), with a minimum for small frames.
   - The video header's old `fec_group` field becomes `fec_groups u8`,
     `fec_parity u8` (per group) and 2 reserved bytes. Parity packets have
     `packet_index >= packet_count`.
   - `/tools/losssim` runs the stream through random and Gilbert–Elliott
     burst loss. FEC must recover at 5% random loss (CLAUDE.md).
2. **NACK and pacing** (NACK in m4-test6, ADR 0021; pacing later):
   - The viewer re-requests missing packets at once; the host keeps about
     100 ms of sent packets.
   - A short reorder window holds a newer frame while an older one is being
     recovered.
   - Packets are sent on their own thread, paced by a token bucket.
   - The stream also carries audio (stream 1, M4b), with the same recovery.
3. **No full keyframe after loss** (see ADR 0022: no periodic IDRs, the
   hitch measured; reference invalidation deferred): NVENC reference-frame
   invalidation, or intra refresh. On the Mac, whatever VideoToolbox
   offers, with fallback.
4. **The network itself** (m4-test11, ADR 0023; the MTU probe deferred): QoS marking (qWAVE /
   `SO_NET_SERVICE_TYPE`), an MTU probe, picking the right interface, and
   keep-awake heartbeats.
5. **Wi-Fi stats** (m4-test12, ADR 0024): link stats, and spike classification with
   named causes (AWDL, scans, power save).

## Consequences
- Each step changes the stream, so the protocol version goes up and both
  ends update together.
- FEC costs bandwidth: about 10–20% more at typical loss, and more under
  heavy loss. M5's rate control will budget it.
