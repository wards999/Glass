# M1 — Offline pipeline: results

**Status: DRAFT. Windows half measured; Mac half verified in CI only.** M1 is
done once the Mac numbers below are filled in from a real Mac.
**Date:** 2026-11-20 · **CI run:** 44643409364 (all green)

## What works
- **Windows host** (`glass record`): Windows.Graphics.Capture → GPU copy into an
  FFmpeg D3D11 frame pool → `hevc_nvenc` (p1/ull, zerolatency, delay 0, no
  B-frames, CBR 80 Mbps, ~1-frame VBV) → `.glsr`. No CPU copies of frames.
  4:2:0 (Main) and 4:4:4 (Rext) both work on the RTX 4070.
- **Mac client** (`GlassMac play`): `.glsr` parsed by core → length-prefixed
  conversion in core → `VTDecompressionSession` (hardware, real-time) →
  IOSurface-backed `420v`/`444v` pixel buffers → `CVMetalTextureCache` (zero
  copy) → YCbCr→RGB shader using the stream's colour matrix → `CAMetalLayer`,
  paced by `CADisplayLink` at capture timestamps. `--bench` decodes as fast as possible.
- **core**: `.glsr` format, Annex-B NAL and access-unit splitting, parameter sets,
  length-prefixed conversion, stats ring (p50/p99/stddev). 19 Rust unit tests.
- **Tests**: 6 XCTests in CI, covering fixture parse, 4:2:0 and 4:4:4 hardware
  decode, an offscreen Metal render check, and rejecting garbage. The Windows CI
  job round-trips the fixtures through `dump`/`pack`.

## Measured — Windows host (RTX 4070, Win11, 2560×1440 @ 165 Hz, 10 s, normal desktop activity)

| | encode p50 | encode p99 | encode max | avg bitrate | first IDR | frame p50 / max | frames |
|---|---|---|---|---|---|---|---|
| HEVC 4:2:0 | 3.35 ms | 17.68 ms | 18.51 ms | 20.0 Mbps | 59 KB | 56 / 92 KB | 470 |
| HEVC 4:4:4 | 4.71 ms | 11.03 ms | 11.90 ms | 17.5 Mbps | 61 KB | 48 / 191 KB | 459 |

"Encode" = frame arrival in Glass → encoded packet out. A 3 s run with more
on-screen motion gave 4:2:0 p50 2.00 ms, p99 4.28 ms (n=295).

- **Target (SPEC §8) is 2–5 ms.** The p50s meet it. The p99s don't in the 10 s runs.
  Likely cause: the GPU/NVENC clocks drop between sparse frames (~47 fps captured
  from a mostly idle desktop). Revisit in M5/M7 (e.g. NVENC directly, or keep
  the encoder warm).
- **Capture interval** p50 6.06 ms (165 Hz) when the screen is changing. Gaps of
  hundreds of ms are idle periods, which is expected with only-on-change capture.
- **WGC timestamp:** `SystemRelativeTime` is *ahead* of arrival for about 98% of
  frames (p50 3.5 ms, max 7 ms). It's a present-target time, so Glass uses
  arrival as the capture timestamp (ADR 0002).

## Known issues
- `app-win/build.rs` copies the FFmpeg DLLs next to `glass.exe` locally but not
  on the CI runner. CI puts `third_party/ffmpeg/bin` on `PATH` instead. Cause not
  found yet.
- NVENC's RGB input gives a BT.601 limited-range stream (FFmpeg forces the VUI).
  The client follows the stream's matrix, so colours are consistent. A BT.709
  conversion of our own can come later if needed.
- Resolution changes mid-recording are skipped (LATER(M7)). The mouse cursor
  isn't captured (LATER(M3)).
- Mac decode is synchronous and allocates CF objects per frame (LATER(M5)).
- Build locally with the MSVC toolchain inside a VS environment (`vcvars64`).
  The GNU toolchain can't link FFmpeg's `.lib` files.
