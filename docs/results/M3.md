# M3 — Input: results

**Status: DRAFT.** Built and verified in CI and on the dev PC (loopback);
waiting for the real Mac → PC test with build `m3-test1`.
**Date:** 2026-11-20

## What works
- **Protocol v2** (`docs/protocol.md`, ADR 0004): loss-tolerant input
  datagrams (recent events repeated, state reconciled), pointer shape and
  visibility over TCP, `input_seq` in each frame for input → screen latency.
- **core**: `InputSender`/`InputApplier`, key tables (Mac kVK → HID → Windows
  scan code, Mac-/PC-style modifiers, ISO keyboards). 54 Rust tests,
  including 2000 key events through 20% random loss with nothing left stuck
  and ≥ 99% delivered exactly once, plus an input + pointer round trip over loopback.
- **Windows host**: `SendInput` injection on the UDP thread (absolute pointer on
  the captured monitor, scan codes, both wheels, back/forward buttons),
  pointer shape capture (works on the real arrow cursor in tests), everything
  released when the session ends, "blocked by Windows" count for elevated windows.
- **Mac viewer**: pointer, buttons, precise scrolling, keys (local monitor,
  ⌘ keyUp workaround, Caps Lock), PC pointer drawn as the Mac cursor,
  ⌃⌥⌘ chords for Glass, PC-style modifier toggle, input → screen in the
  overlay and results. 12 XCTests in CI.

## Known issues
- macOS keeps ⌘Tab, ⌘Space and Mission Control; no relative mouse mode (games).
- Keys are physical; both machines need the same keyboard layout.
- Elevated windows need an elevated host; no UAC/lock screen.
